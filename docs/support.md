## Contributing and Support

Use the repository's Issues area for reproducible bugs and feature requests, and submit focused pull requests for changes. Include the source revision, Python version, operating system, reproduction steps, expected/actual behavior, and relevant logs. Remove passwords, session cookies, personal messages, and `.env` secrets before sharing diagnostics.

When contributing, use generic names, `example.com` addresses, and sample content. Update the project documentation for user-facing changes, keep built-in translation dictionaries aligned when adding interface labels, and describe the checks performed in the pull request. Do not commit runtime databases, uploads, backups, credentials, or your virtual environment.

For security-sensitive reports, do not publish exploit details or private data in a public issue. Follow the private disclosure instructions in [SECURITY.md](../SECURITY.md).
